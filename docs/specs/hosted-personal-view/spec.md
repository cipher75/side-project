# 개인용 호스팅 화면

PC에서 도는 사무실 화면을 내 다른 기기(모바일, 다른 PC)에서도 볼 수 있게, 줄인 상태를 Vercel에 올린 읽기 전용 화면으로 보여줍니다. 앱 전체의 전제는 루트 [PRODUCT.md](../../../PRODUCT.md)를 따릅니다.

## 참고 자료

- [local-first-deployment](../../decisions/local-first-deployment.md): 무엇이 PC를 떠나는지, 누가 접근하는지, hook이 어디로 가는지를 정한 결정입니다. 이 스펙의 모든 경계는 이 결정을 따릅니다.
- [office-activity-view 스펙](../office-activity-view/spec.md)과 [prototype.html](../office-activity-view/prototype.html): 사무실 장면, 캐릭터 동작, 허용 대기, 허용됨, 거절됨, 중단됨, 불 켜짐과 꺼짐의 기준입니다. 호스팅 화면은 이 동작을 그대로 따르고, 여기서는 다시 정하지 않습니다.
- [ui-composition](../../decisions/ui-composition.md): 토큰 입력 화면과 안내 같은 일반 UI의 구성 기준입니다.

## 사용자에게 보이는 결과

- 사용자는 모바일이나 다른 PC의 브라우저에서 호스팅 주소를 열고, 보기 토큰을 한 번 넣으면 PC의 세션들이 사무실로 보입니다.
- 허용 대기(`?`)와 일이 모두 끝난 상태(불 꺼짐)를 PC 앞에 없어도 알아차립니다.
- 화면은 보여주기만 합니다. 허용 여부는 계속 Claude Code, 데스크톱 앱, 모바일 앱에서 정합니다.

## 범위

- 호스팅 화면(읽기 전용), PC의 로컬 서버가 줄인 상태를 호스팅으로 전달하는 일, 접근 토큰을 포함합니다.
- PC의 로컬 화면과 hook 처리는 바뀌지 않습니다. 로컬 화면은 지금처럼 모든 라벨을 보여줍니다.
- 한 사람이 쓰는 개인용입니다. 계정과 로그인은 없습니다.

## 동작과 인수 기준

### 접근
- 보기 토큰 없이 호스팅 주소를 열면 토큰 입력 화면만 보입니다. 세션 이름과 상태는 어느 것도 보이지 않습니다.
- 올바른 보기 토큰을 넣으면 사무실이 보이고, 그 기기는 다시 묻지 않습니다. 토큰은 주소에 담지 않습니다.
- 토큰이 틀렸거나 바뀌었으면 다시 토큰 입력 화면이 나옵니다.
- 보기 토큰으로는 상태를 올릴 수 없고, 보내기 토큰으로는 화면을 볼 수 없습니다. 보내기 토큰이 없거나 틀린 전달은 받지 않습니다.

### 같은 화면
- 호스팅 화면은 로컬 화면과 같은 사무실 장면과 같은 캐릭터 동작을 보여줍니다. 수행 중, 허용 대기, 허용됨, 거절됨, 중단됨, 퇴근, 불 켜짐과 꺼짐이 모두 [office-activity-view 스펙](../office-activity-view/spec.md)의 기준대로입니다.
- 세션은 탭으로 나뉩니다. 둘 이상의 PC에서 올린 세션은 PC 이름과 함께 따로 보입니다. (가정)
- 좁은 모바일 화면에서도 허용 대기 `?`가 가려지지 않습니다.

### 보내는 내용
- PC를 떠나는 것은 호출의 상태와 종류, 말풍선 라벨, 세션 이름, 완료 건수입니다.
- 말풍선 라벨은 도구 이름, 파일 이름, skill 이름, sub-agent 이름뿐입니다. 명령 내용, URL, 검색어, 프롬프트, 전체 경로, transcript 내용은 보내지 않습니다.

  | 호출 | 로컬 화면 | 호스팅 화면 |
  |---|---|---|
  | 파일 읽기 | `Read · PRODUCT.md` | `Read · PRODUCT.md` |
  | 명령 실행 | `Bash · bun run typecheck …` | `Bash` |
  | 웹 가져오기 | `WebFetch · code.claude.com` | `WebFetch` |
  | skill | `skill · shadcn` | `skill · shadcn` |
  | sub-agent | `서브에이전트 · Explore` | `서브에이전트 · Explore` |

- 허용 대기 말풍선의 설명도 같은 기준으로 줄인 라벨을 씁니다.
- 로컬 서버가 로컬 화면에는 모든 라벨을, 호스팅에는 줄인 라벨만 보냅니다. 줄이는 일은 PC를 떠나기 전에 로컬 서버에서 끝납니다.

### 갱신과 끊김
- PC에서 호출이 시작되면 몇 초 안에 호스팅 화면에도 캐릭터가 나타납니다. 허용 대기, 허용됨, 거절됨, 중단됨, 퇴근도 마찬가지입니다.
- 호스팅 전달이 실패하거나 느려도 hook 응답과 로컬 화면에는 영향이 없습니다. 인터넷이 끊긴 동안의 변화는 연결이 돌아오면 최신 상태 하나로 따라잡습니다.
- PC에서 소식이 끊기면(PC가 꺼짐, 로컬 서버가 꺼짐, 인터넷이 끊김) 호스팅 화면은 "PC에서 소식이 끊겼어요 · 마지막 상태 N분 전"을 띄우고 마지막 상태를 흐리게 유지합니다. 끊긴 화면이 "모두 끝남"(불 꺼짐)처럼 보이지 않게 하기 위해서입니다. 소식이 다시 오면 거둡니다.
- 화면이 호스팅과의 연결이 끊긴 것을 알아채면 [office-activity-view 스펙](../office-activity-view/spec.md)의 연결 끊김 안내를 같은 방식으로 보여줍니다.
- 로컬 서버가 다시 켜지면 그전의 허용 대기는 사라졌을 수 있으니 확인하라는 안내를 호스팅 화면에서도 같은 방식으로 보여줍니다.

### 보관
- 호스팅에는 현재 상태만 둡니다. 지난 활동 기록은 두지 않습니다.
- 세션이 끝났거나 오랫동안 소식이 없는 세션은 호스팅에서 지웁니다. (가정: 몇 시간)

## 확정한 제약과 이유

- **수집과 판정은 PC의 로컬 서버:** hook은 `127.0.0.1`로만 보냅니다. 거절됨, 중단됨, 허용됨 판정과 백그라운드 sub-agent 종료가 PC의 transcript에서만 알 수 있어서입니다. 근거는 [local-first-deployment](../../decisions/local-first-deployment.md)입니다.
- **줄인 상태만 PC 밖으로:** 위 "보내는 내용" 표의 라벨만 나갑니다. 한번 나간 내용은 되돌릴 수 없기 때문입니다.
- **개인용, 토큰 둘, 계정 없음:** 보내는 쪽과 보는 쪽의 토큰을 나눠서, 기기에 둔 보기 토큰이 새도 상태를 위조할 수 없게 합니다.
- **보기 전용:** 호스팅 화면에서 허용하거나 거절하지 않습니다.
- **Vercel, GitHub 연동 배포:** 저장소에 올리면 호스팅에 배포됩니다.

## 가정 (바꿀 수 있음)

- 토큰은 둘입니다. 보내기 토큰은 PC의 로컬 서버에만 두고, 보기 토큰은 기기마다 한 번 입력해 브라우저에 기억합니다. 토큰을 바꾸면 기기는 다시 입력합니다.
- 세션 이름(프로젝트 폴더 이름)은 호스팅으로 보냅니다. 탭의 이름이기 때문입니다.
- 여러 PC의 세션은 PC 이름으로 구분해 한 화면에 모읍니다.
- 갱신은 몇 초 단위, 소식이 끊긴 것으로 보는 기준은 수십 초, 세션 정리는 몇 시간 단위입니다. 정확한 값은 구현에서 정하고 이 스펙에는 허용 범위만 둡니다.

## 범위 밖

- 여러 사용자, 계정, 로그인, 공유: 개인용 결정에 따라 제외합니다.
- 호스팅 화면에서 허용이나 거절 처리: 처리는 앱과 모바일의 몫입니다.
- 모바일 푸시 알림과 이메일 알림: 요청하지 않았습니다. 화면을 열어 둔 사용자가 허용 대기를 놓치지 않는 데까지만 다룹니다.
- 지난 활동 기록 보관과 재생: 요청하지 않았습니다.
- hook이 호스팅 주소로 직접 전송하는 경로: 결정 문서에서 제외했습니다.

## 보류한 결정

- **호스팅의 저장 기술과 갱신 방식:** 구현을 정할 때 고릅니다. 후보는 Vercel 마켓플레이스의 저장소(Blob, Redis 등)이며, Vercel 서버리스는 서버 메모리와 오래 유지되는 연결(SSE)이 맞지 않는 점을 반영해야 합니다. 어느 쪽이든 "보내는 내용" 경계 안이어야 합니다.
- **로컬 서버를 안정적으로 켜 두는 방법:** `next dev` 대신 빌드한 서버로 돌리는 것을 포함해, 호스팅 전달이 꺼지지 않게 하는 방법입니다. [office-activity-view 스펙](../office-activity-view/spec.md)의 남은 위험과 같은 문제입니다.
- **토큰 교체 절차:** 토큰이 새었을 때 바꾸는 방법과 기기 정리의 세부입니다.

## 남은 위험

- 호스팅 화면을 열어 두지 않으면 허용 대기를 놓칩니다. 알림이 없기 때문에, 이 기능은 놓치기 쉬운 상황을 "열어 둔 화면에서 보이게" 하는 데까지만 줄여 줍니다.
- 줄인 라벨에도 파일 이름은 들어갑니다. `.env`처럼 이름 자체가 민감한 파일이 보일 수 있습니다.
- 토큰이 새면 상태를 볼 수 있습니다. 보기 토큰만 새면 위조는 못 하지만 열람은 됩니다.
- PC의 로컬 서버가 꺼져 있으면 호스팅은 마지막 상태만 보여줍니다. 소식이 끊김 안내가 이를 알려줍니다.
- Vercel의 무료 사용 한도와 서버리스 제한이 갱신 간격을 제한할 수 있습니다. 개인용 규모에서 한도를 넘는지는 구현 전에 확인해야 합니다.
- 로컬 서버의 transcript 판정이 틀리면(기존 스펙의 위험) 호스팅 화면도 같은 결과를 보여줍니다.
