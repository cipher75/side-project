# 허용 창이 떠 있는 동안 보낸 프롬프트의 거절 오인

## 증상
허용 요청 창이 떠 있는 동안 `UserPromptSubmit`이 먼저 오면, 아직 허용 여부를 정하지 않은 호출의 캐릭터가 거절로 추정되어 퇴근한다. 이후 사용자가 허용해도 그 캐릭터는 이미 나간 뒤다.

## 증거
`features/office-activity/session-state.ts`의 `UserPromptSubmit` 처리가 허용 대기 캐릭터를 모두 거절로 바꾼다. 코드 리뷰(`code-review low`)가 지적했다. 허용 창이 떠 있을 때 프롬프트를 미리 보낼 수 있는지는 실제 세션에서 확인하지 못했다.

## 추정 원인
거절을 알려주는 이벤트가 없어서 다음 이벤트로 추정하는 규칙이다. 스펙은 새 프롬프트를 거절 신호로 정했다.

## 다음 단계
허용 창이 떠 있는 동안 프롬프트를 보내 보고, 그때 `UserPromptSubmit`이 오는지 확인한다. 오면 새 프롬프트 대신 일정 시간이 지난 뒤에만 거절로 보는 규칙을 스펙에서 정한다.
